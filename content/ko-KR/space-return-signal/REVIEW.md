# 우주 정거장의 귀환 신호 · 콘텐츠 검수 기록

**0.9.0 편집 · 2026-10-29.** `return_order.prompt`에서 방금 읽은 순서를 다시 설명하는 문장을 덜어 ‘문이 아직 열려 있네. 문 닫기부터 할까, 출발 신호부터 보낼까?’로 줄였다. 확인표·하나둘 세기라는 앞 선택의 결과와 우주선 탑승→문 닫기→신호의 순서는 그대로다. 새로운 절차·사실·선택이나 실제 우주선 운용 지침을 추가하지 않는다.

버전과 귀환 질문 한 곳 외의 행동·선택 이름·별칭·분기·점수·자원·단서·flag·역할·차례·결말은 유지한다. 실제 D 전달본의 0.8.0 원문 18,237바이트와 줄바꿈을 `content/legacy/0.8.0/space-return-signal/episode.json`에 그대로 보존했다. SHA-256은 `a463aa211b5a7225788de6ce9a164608a057be01a674b8a64de73ffc556ad1fc`다.

세 편 공통 `tests/test_content_narrative_connections.py` 62개가 통과했다. 이 편은 두 준비 방식×1인·2인의 연결에서 앞선 결과를 다시 설명하지 않는지, 두 정확한 응답과 탑승·귀환 순서가 유지되는지 검사한다. 각 인원의 64경로에서 0.8→0.9 비서사 상태·선택명·별칭 해석·결말 동일성을 비교했고, 두 판 모두 content checker를 통과했다. 실제 TTS 시간·아동 청취 이해도 검증은 아니다. Android 자산·실행 범위는 해당 앱의 별도 검증 기록을 따른다. 아래는 이전 판의 당시 기록이다.

**0.8.0 편집 · 2026-10-28.** 두 결말의 일반적인 기록 회상을 이번에 고른 관측 장면으로 교체했다. 기존 `mission`·`tool_used`·`record`를 평면 `template_labels`로 읽어, 사진에는 달의 충돌구/화성의 붉은 먼지를 한눈에/가까이 본 **모습**, 노트에는 그렇게 본 **이야기**가 남았다고 말한다. 결말은 세 문장을 유지하며 다른 관측 방식이나 실제로 하지 않은 설명·그림 수행을 덧붙이지 않는다. 두 아이의 역할은 모두 **탐사 친구**다. 첫 아이부터 교대하는 기존 여섯 차례를 유지하며 특정 아이만 관측이나 귀환을 담당한다고 부르지 않는다.

귀환은 돌아갈 **우주선**에 토리와 오누가 함께 탄 뒤 문을 닫고 신호를 보내는 순서로 대사를 맞췄다. 로봇 토리 자체에 문이 있거나 문을 닫은 뒤 오누가 타는 설명을 없앴다. 질문에서 직접 쓰는 **문 닫기부터**·**출발 신호부터** 두 표현만 해당 행동의 별칭으로 추가했다. 기록 목적어는 `record_object`로 구분해 ‘풍경 사진을’·‘관찰 노트를’로 읽는다. 실제 운용 지침을 추가한 것이 아니며 기존 행동·분기·점수·자원·단서·flag·차례·사실 출처는 유지한다.

실제 전달된 앱 0.14의 우주 0.7.0 원본 16,784바이트와 카탈로그 메타데이터는 `content/legacy/0.7.0/space-return-signal/episode.json`에 보존했다. 이전 세션에는 새 대사·역할명·두 별칭을 적용하지 않는다. `tests/test_content_space_recall.py`의 48개 시험은 16가지 결말 조합 × 1인·2인의 실제 선택 회상, 양 인원의 각 64경로 상태 효과 보존, 여섯 질문의 이름·차례·역할, 탑승 순서, 목적격 조사, 새 별칭의 부정·복수·차례·제어 경계를 확인한다. 새 Android 복제본·비교 자료 생성과 전체 191개 통합 실행은 [앱 0.15 최종 검증 보고서](../../../docs/verification-onu-0.15.0-2026-10-28.json)에 APK·XML 해시와 함께 연결했다. 실제 아동 이해도·반복 이용 몰입·TTS 청취는 아직 검증하지 않았다. 아래는 이전 판의 기록이다.

**0.7.0 편집 · 2026-10-27.** 마지막 선택 결과는 친구들이 모이거나 둘러앉는 준비로 줄였다. 선택한 공유 방식과 행성·기록은 기존 결말에서 완성한다. 0.11 배포 APK의 0.6.0 원문과 카탈로그 메타데이터는 보존했다. 장면·행동 ID, 분기·점수·자원·단서·flag·출처와 결말 본문은 유지한다. 글로벌 기다림·거절·쉬기와 무응답 정책은 바꾸지 않았다. 아래는 이전 판의 검수 기록이며 실제 가족 청취·교육 효과 검증을 뜻하지 않는다.

**0.5.0 편집 · 2026-10-27.** 귀환 준비에서 순서를 미리 반복하던 문장을 줄이고, 확인표 읽기와 하나둘 세기는 오누가 수행한다고 명시했다. 필요한 순서는 선택 뒤 안내에 유지하며 탐사 기록을 함께 가져오는 흐름을 살렸다. 0.4.0 원문은 바이트 그대로 보존했고, 기존 행동 ID·별칭·분기·점수·자원·단서·flag·출처는 바꾸지 않았다. 새 입력 기능이나 교육 효과 주장을 추가하지 않았으며, 실제 가족 청취 평가는 미실시다. 아래는 0.3.0 당시의 검수 기록으로, 그때의 문구·시험 수를 이번 판의 결과로 읽지 않는다.

`space-return-signal` `0.3.0` · `interest_tags: [space]` · `play_style: solve` · 2026-10-27

관측 장소 → 관측 도구 → 가져갈 기록 → 귀환 협력 → 먼저 할 일 → 공유 방법의 여섯 선택이다. 이번 판의 작은 목표는 친구들에게 전할 발견을 가져오는 것이다. 시작에서 상상 탐사임을 알리고, 달·화성에 도착해 관찰한 뒤 기록을 챙겨 정거장으로 돌아온다. 전시와 이야기 나누기 모두 같은 목표를 이루며 어느 공유 방식을 더 좋다고 평가하지 않는다.

0.3.0에서는 도구 선택의 결과를 바로 다음 기록 장면에 연결했다. 넓은 화면을 고르면 “한눈에 본 풍경”, 확대 카메라를 고르면 “가까이 본 모습”을 남긴다. 사진·노트 선택은 귀환 준비와 결말에, 확인표·순서 세기는 귀환 순서를 묻는 장면에 반영된다. 결말은 장소와 기록 방식, 마지막 공유 방식만 짧게 회수한다. 모든 선택을 한 문장에 나열하거나 이전 방문을 기억한다고 말하지 않는다.

NASA Science의 [Moon Craters](https://science.nasa.gov/moon/lunar-craters/)와 NASA JPL의 [Exploring the Colors of Mars](https://www.jpl.nasa.gov/edu/resources/lesson-plan/exploring-the-colors-of-mars/)에 근거한 기존 두 사실을 유지한다. 달의 충돌구는 우주 물체의 충돌 흔적이고, 화성 먼지의 붉은빛은 산화철과 관련이 있다. 출처 확인일은 2026-10-26이며 이번 개정에서 새로운 과학 사실이나 출처를 추가하지 않았다. 화성 전체가 같은 색이라고 설명하지 않는다.

탐사 로봇 토리·정거장·귀환 절차·관측 화면·사진·노트는 상상 이야기다. 앱이 카메라를 사용하거나 실제 탐사 사진을 촬영·분석·저장한다는 뜻이 아니다. 귀환 순서는 이야기에서 제시한 ‘문 닫기 → 출발 신호’를 함께 확인한다. 신호를 먼저 고르면 열린 문을 확인하고 순서를 바로잡아 귀환한다. 실제 우주선 운용 방법이나 실제 차량 제어로 표현하지 않는다.

두 결말은 작은 전시와 탐사 이야기 공유다. 기존 장면·행동 ID, 별칭, 분기, 단서, 자원, 점수, 출처를 유지한다. 모든 행동은 내부 1점이며 여섯 선택을 마치면 총 6점, 두 명이면 각 3점이다. 힌트 여섯 번에 감점이 없고, 기록·협력·공유 취향이나 순서 실수를 점수 차이로 평가하지 않는다. 0.2.0 원문은 별도 archive에 보존한다.

6–9세 중심은 설계 가설이다. 초면에는 목표와 토리를 소개하고, 질문은 하나씩 제시하며 필요한 앞선 선택을 가까운 장면에서 다시 알려 준다. 재방문에는 실제 이번 판의 선택만 반영한다. 새 대사의 실제 아동 이해도·기억 부담·재미·TTS 청취·가족 사용성은 아직 검증하지 않았다.

전용 Python 시험 tests/test_content_space_vehicles.py는 관측 도구별 후속 안내, 기록별 귀환·결말, 협력 방식의 재사용, 모든 1인·2인 각 64경로의 여섯 선택과 두 결말, 단일 질문과 세 문장 이내 결말, 0.2.0 대비 규칙·별칭·출처 보존을 확인한다. 이 파일의 두 편 시험 33개와 해당 팩 content checker가 통과했다. 현재 개정의 Android parity/실기기 실행 결과는 별도 통합 기록으로 확인해야 한다. 과거 fixture 발화 수를 현재 개정의 실행 수치로 재사용하지 않는다. 약 4–6분은 측정값이 아닌 예상이다.
