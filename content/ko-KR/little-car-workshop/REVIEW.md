**0.5.0 편집 · 2026-10-27.** 오누와 두리의 배달을 준비하고 배웅하는 흐름으로 말투를 다듬었다. 먼저 꺼낼 상자와 안쪽에 둘 상자를 짧게 구분하고, 마지막 인사는 오누가 수행한다. 0.4.0 원문은 바이트 그대로 보존했고, 기존 행동 ID·별칭·분기·점수·자원·단서·flag·출처는 바꾸지 않았다. 새 입력 기능이나 교육 효과 주장을 추가하지 않았으며, 실제 가족 청취 평가는 미실시다. 아래는 0.3.0 당시의 검수 기록으로, 그때의 문구·시험 수를 이번 판의 결과로 읽지 않는다.

`little-car-workshop` `0.3.0` · `interest_tags: [vehicles]` · `play_style: solve` · 2026-10-27

배송물 → 주문 조건 → 짐칸 준비 → 점검 도구 → 상차 순서 → 인계 방식의 여섯 선택이다. 아이와 오누는 상상 정비소에서 두리의 배달 준비를 돕는다. 화분은 키와 열린 짐칸, 책은 비와 덮개를 고려한다. 다른 차를 골라도 높은 덮개·상자용 비 덮개를 준비하는 별도 단서와 피드백으로 이어지고, 고른 차를 다른 차로 바꾸지 않는다.

0.3.0에서는 준비와 상차의 순서를 맞췄다. 세 번째 선택에서는 빈 짐칸·받침·덮개를 준비하고, 네 번째 선택에서는 멈춘 두리의 옆면 고리를 살핀다. 실제 상자를 싣는 서술은 다섯 번째 선택에서 한다. 이미 짐을 실었다고 말한 뒤 처음 실을 상자를 다시 묻던 표현을 없앴다. 고른 차는 다음 점검 안내에, 점검등·거울은 인계 안내에 다시 등장한다.

화분 배달은 별 상자를 먼저 내리므로 달 상자를 안쪽에 먼저 싣는다. 책 배달은 달 상자를 먼저 내리므로 별 상자가 안쪽이다. 먼저 꺼낼 상자를 질문에서 다시 알려 주므로 앞선 주문표를 외워야만 고를 수 있는 구조는 아니다. 다르게 고르면 먼저 꺼내기 어려운 이유를 설명하고 두리와 위치를 바꿔 싣는다. 이때도 같은 여섯 선택과 완료 점수를 유지한다.

말하는 자동차·짐칸 규격·도로 밖 상상 정비소·두 상자 규칙은 모두 허구다. 새 과학·교통·적재 사실이나 외부 출처를 추가하지 않았다. 실제 운전·수리·적재 교육의 효과를 주장하지 않으며, 실제 차량의 문·등·고리를 조작하도록 안내하지 않는다. 점검과 고리 잠그기도 이야기 안에서 멈춰 있는 두리가 하는 일이다.

두리에게 차례표를 읽어 주는 결말과 배달 친구에게 확인표를 건네는 결말 모두 준비의 완료다. 결말은 실제 배송물·목적지·먼저 꺼낼 상자와 인계 방식을 세 문장 안팎으로 회수한다. 선택한 차와 도구는 앞선 장면에서 이미 연결하므로 끝에 다시 길게 나열하지 않는다. 아직 실행하지 않은 배달이 끝났다거나 목적지에 도착했다고 기록하지 않는다.

기존 장면·행동 ID, 별칭, 분기, 단서, 자원, 점수는 유지한다. 행동마다 내부 1점, 총 6점이며 두 명이면 각 3점이다. 힌트 여섯 번에 감점이 없고, 차를 보완하거나 순서를 다시 확인해도 같은 완료 점수다. 0.2.0 원문은 별도 archive에 보존한다.

6–9세 중심은 설계 가설이며 실제 아동 시험 결과가 아니다. 첫 장면에서 목표를 소개하고, 한 번에 한 질문을 하며 관찰한 조건을 다음 선택에 이어 준다. 재방문 대사도 이번 판에 실제로 고른 내용만 말한다. 실제 음성 청취, 두 아이의 공동 놀이, 재미·난도·차량 내 이해도는 별도 검증이 필요하다.

전용 Python 시험 tests/test_content_space_vehicles.py는 네 가지 배송물·차 조합에서 상차 전 준비만 서술하는지, 양쪽 상차 선택 이후 실제 적재 결과가 나오는지, 점검 도구를 인계 장면에서 회수하는지, 두 배송물과 두 인계 결말의 기억이 서로 섞이지 않는지 확인한다. 모든 1인·2인 각 64경로의 여섯 선택과 두 결말, 단일 질문과 세 문장 이내 결말, 0.2.0 대비 규칙·별칭 보존도 검사한다. 이 파일의 두 편 시험 33개와 해당 팩 content checker가 통과했다. 현재 개정의 Android parity/실기기 결과는 별도 통합 기록으로 확인해야 한다. 약 4–6분은 예상 시간이다.
